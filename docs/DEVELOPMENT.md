# 模块结构与开发验证

[返回 README](../README.md) · [配置手册](CONFIGURATION.md)

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `main.py` | 读取配置，注册固定指令、明确编号入口及 LLM 工具 |
| `download_commands.py` | 识别完整的 JM/NH 来源与编号，兼容大小写、空格和 `/` |
| `search_workflow.py`、`client.py`、`models.py` | soutubot 请求、结果解析和展示 |
| `findchicken_workflow.py`、`findchicken_client.py`、`findchicken_models.py` | 独立找鸡任务、并行查询、作者与通用网页展示、同来源页去重 |
| `google_lens_client.py` | SerpAPI 上传与检索、通用结果解析、独立超时、跨入口有界缓存与进行中请求合并 |
| `routing.py` | 从同一达标作品的来源中选择 NH、JM 或仅返回结果 |
| `multi_search.py`、`engines/` | 按需并行搜索，各来源独立处理异常与结果缓存 |
| `jm_workflow.py`、`jm_resolver.py`、`jm_llm.py` | JM 标题查询、作者兜底和模型辅助核验 |
| `jm_source.py`、`nh_downloader.py` | 各自下载图片，返回有序图片清单 |
| `download_service.py` | 下载任务合并、并发控制、图片清单与 PDF 缓存 |
| `pdf_service.py` | 图片转换、PDF 加密、页数与加密状态验证 |
| `download_workflow.py`、`file_delivery.py` | 下载到发送的流程编排、发送结果判断与文件保留 |
| `policy.py`、`workflow_common.py` | 白名单、搜索冷却、参数范围和找本/搜本下载确认 |

`jm_downloader.py` 与 `jm_send_patch.py` 保留兼容入口。JM 库、PDF 依赖和多引擎客户端按需使用。

下载器不负责搜索与文件发送；PDF 模块不负责选择来源；明确编号入口与普通指令共用下载队列和权限规则。某个来源请求失败，不会取消其他独立来源的结果。

`/找本` 与 `/搜图` 独立注册，通过 `_start_image_search` 共用图片读取、白名单、冷却和任务准入。`/找本` 进入 `_background_search`，保留 soutubot 与来源分流，匹配到可下载作品后登记 JM/NH 来源、编号和配置有效期，等待原查询者在原会话回复确认后进入下载队列；`/搜图` 直接进入 `_background_multi_search`，该流程也用于找本兜底，不执行 JM 查询或下载。

明确编号入口使用高优先级自定义过滤器。带空格时可能同时匹配原固定指令，但处理器会先停止事件传播，再进入下载队列，从而避免重复下载和继续进入普通 LLM 对话。

## 本地验证

在仓库根目录，使用 Python 3.11+ 的独立环境安装依赖后运行：

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

测试覆盖来源分流、相似度阈值、并行来源失败隔离、明确编号格式、LLM 开关联动、JM/NH 下载适配、任务合并、PDF 生成与密码，以及发送失败后的保留行为。

这些测试使用模拟网络和消息接口，不会主动下载外站作品或向 QQ 发送消息。PDF 测试会实际创建并验证临时文件。

## 安装后的验证

| 环节 | 检查内容 |
| --- | --- |
| 插件加载 | 元数据版本正确，固定指令及四个 LLM 工具注册成功 |
| 明确编号入口 | 分别测试 JM/NH 的大小写、空格和 `/` 组合，每条只进入一次下载 |
| 找本分流 | 达标 NH 优先；EH 进入 JM 查询；未达标或请求失败时才使用已启用的多引擎 |
| 直接搜图 | `/搜图` 只调用多引擎，不访问 soutubot、不查询 JM、不下载；总开关关闭时明确提示 |
| 找鸡 | 先确认后请求；图片、引用、链接和 QQ 自动 @ 均可触发；Pixiv/X 输出、独立开关及冷却、卸载取消任务 |
| Google Lens | URL 与 500 KB 图片上传；并行而非兜底；部分成功保留；无伪造账号/分数；同图缓存、同源去重、取消与密钥脱敏 |
| LLM 开关 | 关闭总开关后，固定编号仍能下载，JM 查询不再调用模型 |
| PDF | 页数、顺序、密码和大小符合预期 |
| 文件发送 | 核对当前会话实际收到的文件；适配器返回成功不等于用户阅读回执 |

离线测试、插件注册、外站连通性和 QQ/NapCat 文件送达是不同的验证环节，需要分别确认。发送结果不确定时先检查群文件或私聊记录，不自动重试，以免重复发送。

## 发布包

手动安装包应包含插件根目录的 Python 源文件、`engines/`、元数据、配置定义、依赖清单、文档和许可证。不要包含 `.git/`、运行数据、下载缓存、日志、凭据或虚拟环境。

发布前检查 ZIP 元数据与源码版本一致、相对文档链接有效、必要模块齐全，并运行测试与差异检查。源码包不包含依赖 wheel；安装依赖仍由 AstrBot 或部署环境完成。

帮助由 `help_text.py` 按当前触发昵称生成；确认时限仅在实际下载询问中展示，入口为 `/搜图帮助`，兼容旧 JM 帮助别名。确认记录在发送失败时清除、消费时同步弹出，过期、其他用户或其他会话不能触发；热重载后待确认记录清空。
